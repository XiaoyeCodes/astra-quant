# 风控层升级、模拟资金重置根因、模拟手续费根因（2026-10-26）

全程模拟盘。下面每一条都在本机模拟盘实测过。

## 一、风控层：三条止损线

每个方案可以单独设置，填 0 表示关闭：

| 规则 | 起算点 | 作用 |
|---|---|---|
| 最大止损 | 方案启动时的资金 | 原有规则，限制总亏损 |
| **回撤止损**（新增） | 运行期间的**最高**资金 | 保护已经赚到的利润：比如涨到 1300 后回撤 10%，在 1170 就止损，而不是等跌破起点 |
| **单日亏损上限**（新增） | 当天（北京时间）第一笔资金 | 限制单日损失，零点自动换日 |

- 三条线里**最高的那条最先触发**，驾驶舱会标出“最先触发”的是哪一条，以及距离它还有多少。
- 任意一条触发后，执行同一套流程：撤单 → 卖出全部持币 → 从 OctoBot 持仓表核实只剩 USDT → 切换到观望。记录里会写明是哪条规则触发的。
- 模拟资金被识别为“重置”时，三条线的起算点会一起重设。
- 参数先全部校验再保存，不会出现只改了一半的情况。
- 实测：单日亏损上限 4%，触发信息为“触发单日亏损上限：权益 992.13，今日起点 1041.74，下跌 4.76%（上限 4%）”，核实只剩 USDT。

## 二、模拟资金被“重置”的根因（已修复）

之前多次出现模拟资金在重启后变回配置的初始资金（2200 → 1000，992 → 1000）。

**根因**：OctoBot 只有在存档里有 `ending_portfolio`（上一次结束时的持仓）时，才会恢复模拟账户；否则按配置的初始资金重建。而**交易者被暂停**（旧版止损的最后一步，以及 OctoBot 内置的备用止损都会暂停交易者）时，OctoBot 保存的存档里**没有** `ending_portfolio`，于是下一次启动就被重置了。

**修复**：止损不再暂停交易者，改为在核实清仓后**切换到“观望”并重启**（观望不下任何单，效果同样是停止交易），并且在重启前等 OctoBot 把卖出后的账户写入磁盘。
- 实测：持有 BTC/ETH/SOL 时触发止损，重启后账户是 **USDT 995.97**（就是卖出所得），存档里的 `ending_portfolio` 也是 USDT 995.97，没有被重置。
- **仍然存在的限制**：OctoBot 内置的备用止损（只在桥接服务停止时才会起作用）仍然依靠暂停交易者，触发后下一次重启时模拟账户可能被重置。这只影响模拟盘；桥接服务的“重置识别”会重设止损基准。

## 三、模拟盘手续费 0.2% 的根因（已修复）

**根因**：实时模拟盘里，OctoBot 通过 ccxt 连接器计算手续费，用的是 ccxt 内置的 Bitget 市场费率（挂单、吃单都是 **0.2%**），配置里的 `trader-simulator.fees`（0.1%）只在回测时生效。所以**之前所有模拟成交都多扣了一倍手续费**，模拟收益偏差。Bitget 现货真实费率是 0.1%（持有 BGB 还能更低）。

**修复**：在启动补丁里，给 Bitget 插件加上 `get_trade_fee`。**只对模拟交易者**改用配置的费率；实盘和合约仍然走原来的计算路径。补丁带标记、可重复执行，代码结构变了就跳过，不会影响 OctoBot 启动。
- 实测：修复后指数持仓的三笔市价买入，手续费都是 **0.1000%**（修复前是 0.2000%）。
