# ASTRA 任务计划书

更新：2026-10-26。这份文件供后续开发（人或 Claude）按任务逐个推进。每个任务都可以单独开始，写明了背景、要做什么、涉及的文件和验收标准。

## 怎么用这份计划书

开新会话时，对 Claude 说：

> 读 `docs/ROADMAP.md` 和 `docs/HANDOFF.md`，按「开发规则」做任务 **T1.1**。先说明要改什么、为什么改，改完跑测试，并在模拟盘上实测。

每做完一个任务：
1. 在下面的「进度表」里把它标成已完成，写上分支或 PR。
2. 在 `docs/HANDOFF.md` 末尾补一段：做了什么、怎么验证的。

## 开发规则（每个任务都适用）

- **只用模拟盘**，不要切换实盘。实盘相关任务（第 4 部分）必须由项目负责人明确同意后才能开始。
- 不要读取或打印 `.env` 里的密钥，也不要提交 `.env`。不要运行 `docker compose config`，它会把 `.env` 展开打印出来。
- 端口只绑定 `127.0.0.1`，不要改成 `0.0.0.0`。
- 不调用紧急停止和撤销全部挂单的接口，除非负责人要求。
- 需要在 OctoBot 网页里填密钥或选择 profile 时，停下来一步步告诉负责人怎么操作，不要让对方把密钥发过来。
- 改代码前先说明改什么、为什么；改完运行：
  - `python -m pytest -q tests`
  - `node tests/test_feed.cjs`
- 提交前执行 `git checkout -- octobot/user/profiles/`。OctoBot 运行时会改写这些 profile 文件，除非是有意修改。
- 用新分支开发，PR 的 base 选当前最新的功能分支（PR 合并前是叠加关系）。
- 访问 Bitget 时，本机 Python 需要代理：`--proxy http://127.0.0.1:7890`。

## P0：先做完再往下

### T0.1 合并 PR #2 → #3 → #4
- **做什么**：按顺序合并，每合并一个就把下一个 PR 的 base 改成 `main`，等 CI 通过后再合并下一个。
- **验收**：`main` 包含全部功能，CI 通过；本机从 `main` 重建容器后，驾驶舱和系统体检都正常。
- **注意**：合并是不可撤回的对外操作，必须由负责人确认。

### T0.2 备用止损不再暂停交易者
- **背景**：桥接服务停掉时，OctoBot 内置的备用止损（ProfitabilityThreshold 自动化）会执行 `StopStrategiesAndPauseTrader`。交易者被暂停后，OctoBot 保存的存档里没有 `ending_portfolio`，下一次启动时模拟账户会被重置成初始资金。
- **做什么**：
  - 研究能否只用 `CancelOpenOrders` + `SellAllCurrencies` 作为备用动作，再用别的方式阻止重新开仓，例如清仓后让策略不再下单。
  - 如果做不到，在停止前强制保存一次模拟账户。
- **涉及文件**：`bridge/app/autopilot.py` 里的 `automation_config`、`record_backup_stop`。
- **验收**：停掉桥接服务，让备用止损在模拟盘触发，之后重启 OctoBot，账户余额不变、没有被重置。补上对应测试。

### T0.3 产品决策（2026-10-27 已决定）

**决定**：① 三个自动方案保留，收进设置里折叠的「实验功能」区，简洁首页和向导不出现；② DCA 改保守参数并重新回测，标「谨慎」；③ 默认推荐现货网格，已在模拟盘启动（止损 10% / 8% / 4%）；④ OctoBot 网页暂不设密码（端口只绑定本机）。

原问题：
1. 三个自动方案（AI 交易、AI 选策略、指标选策略）：隐藏、保留为“实验功能”（现状），还是删掉？
2. DCA 补仓策略回测 −29%：用保守参数，还是从列表里去掉？
3. 默认推荐哪个策略？回测最好的是现货网格 8×0.5%。
4. 要不要给 OctoBot 网页设置密码？设置后要在 `.env` 里填 `OCTOBOT_PASSWORD`。

## P1：让小白能当“脱手掌柜”

### T1.1 每日报告推送
- **前提**：负责人在 `.env` 里配置了一个通知渠道（Telegram、企业微信、飞书、钉钉或 Server 酱）。
- **做什么**：每天北京时间 21:00（可配置 `DAILY_REPORT_HOUR`）推送一条日报，内容包括：
  - 资金和今日盈亏
  - 自方案启动以来的收益，和同期持有 BTC 对比
  - 成交笔数
  - 当前策略和方案
  - 最先触发的止损线和它的距离
  - 体检结果（只列有问题的项）
- 驾驶舱的设置里加一个“立即发送日报”按钮。
- **涉及文件**：新建 `bridge/app/report.py`；`state.py` 增加定时循环；`main.py` 增加路由；`web/` 增加按钮。
- **验收**：
  - 有单元测试，用固定数据生成日报文字。
  - 跨零点时不重复发送、不漏发；桥接服务重启后同一天不重复发送（发送日期持久化到 `data/`）。
  - 实际收到一条测试日报。

### T1.2 小白首页模式
- **做什么**：首页加一个“简洁 / 专业”切换（用 localStorage 记住选择）。简洁模式只显示：
  - 一个大数字：资金，以及今日、累计盈亏
  - 一句话状态，例如“正在用现货网格交易，止损线 900，一切正常”
  - 体检指示灯
  - 两个按钮：“开始”（选推荐策略和止损）和“停止并卖出全部”（复用止损清仓流程，需二次确认）
- **涉及文件**：`web/index.html`、`web/js/panels.js`、`web/css/astra.css`；停止按钮需要后端新接口，复用 `execute_stop`，以人工操作记录。
- **验收**：手机宽度下可用；简洁模式没有专业术语；“停止并卖出全部”在模拟盘实测后只剩 USDT；有测试。

### T1.3 首次使用向导
- **做什么**：第一次打开时（没有任何方案记录）按顺序引导：
  1. 检查连接（复用体检）
  2. 选策略（附回测和持有 BTC 对比）
  3. 设止损（给出推荐值）
  4. 测试通知
  5. 启动
- **验收**：向导可以跳过、可以重新打开；不会自动启动交易，必须由用户点击。

### T1.4 “为什么停了 / 为什么切换了”说明
- **做什么**：止损、自动切换、交接卖出这些事件，在首页用一张卡片说清楚：发生了什么、为什么、现在是什么状态、下一步可以做什么。数据来自 `stopped`、`switching` 和审计日志。
- **验收**：每种事件都有对应文案和测试。

## P2：策略与研究

### T2.1 网格参数稳健性与样本外回测
- **做什么**：
  - 对网格的格数和间距做参数扫描，用前 18 个月选参数、后 6 个月验证（walk-forward）。
  - 输出参数热力图（收益 / 回撤）。
  - 如果最优参数附近收益很不稳定，在文档里说明。
- **涉及文件**：`bridge/app/backtest.py`、`tools/run_backtest.py`、`docs/`。
- **验收**：报告写明样本外收益和回撤，和持有 BTC 对比；推荐参数只在“周边参数也赚钱”时才给出。

### T2.2 模拟盘与回测对账
- **做什么**：用同一段时间的 K 线，对模拟盘实际运行的策略跑一次回测，对比成交笔数、手续费和收益，找出差异原因（成交假设、滑点、OctoBot 行为）。
- **验收**：一份对账报告；差异超过 2 个百分点时要有解释。

### T2.3 行情切换方案：改进或下线
- **背景**：规则切换在所有变体下都亏损（切换太频繁，手续费和来回买卖成本太高）。
- **做什么**：
  - 尝试更粗的判断，例如日线级别、只区分“趋势 / 震荡”两类。
  - 尝试只在震荡时开网格、其余时间空仓。
  - 如果还是跑不赢“只开网格”，建议负责人下线这个方案。
- **验收**：回测报告，包含手续费、切换次数，以及和“只开网格”、持有 BTC 的对比。

### T2.4 AI 判断准确率记录
- **做什么**：把每次 AI 行情判断和之后 24 小时的实际走势存下来，每周统计准确率，在设置里显示。
- **验收**：数据持久化到 `data/`；有统计测试；不额外调用 AI。

### T2.5 多币种回测
- **做什么**：用 `tools/fetch_history.py` 拉 ETH/USDT、SOL/USDT 两年数据，跑所有策略，和各自持币对比。
- **验收**：`docs/` 下的报告和 `backtest_summary.json` 都更新。

## P3：工程与运维

### T3.1 数据备份与恢复
- **做什么**：一个脚本，打包 `data/`（方案配置、止损起点、审计日志、权益历史）和 `octobot/user/profiles/`，备份时排除 `.env`；以及对应的恢复脚本。
- **验收**：备份后删除数据、再恢复，驾驶舱状态一致。

### T3.2 Docker 冒烟测试脚本
- **做什么**：`tools/smoke.py`，对正在运行的容器逐项检查：
  - `/api/health/report`
  - 安全防护：伪造 Host 头应返回 403
  - 模拟盘模式
  - 切换到观望再切回（可选，需加 `--switch` 参数）
- **验收**：一条命令给出通过 / 失败；不会触发止损或紧急接口。

### T3.3 Windows 一键启动与自检
- **做什么**：`start.ps1`，依次检查 Docker Desktop 是否运行、`.env` 是否存在（不存在就从 `.env.example` 复制）、端口是否被占用，然后启动容器并打开驾驶舱。
- 加入已知故障的处理：Docker Desktop 因残留的 `%LOCALAPPDATA%\docker-secrets-engine\engine.sock` 启动失败时（错误窗口写 `initializing Secrets Engine`），自动用 WSL 删除后重启 Docker（2026-10-25、10-27 各发生一次，都是 Windows 关机后）。
- **验收**：新电脑按 README 一条命令能跑起来；脚本不读取、不打印 `.env` 内容。

### T3.4 OctoBot 升级兼容流程
- **背景**：
  - 固定使用 OctoBot 2.1.1。3.0 是节点模式，没有 `/api/*` 接口。
  - `tools/patch_octobot.py` 的补丁带标记，代码结构变了会跳过。
- **做什么**：写升级检查清单和脚本，在新版本容器里检查：各补丁是否打上、API 是否可用、模拟手续费是否为 0.1%。
- **验收**：`docs/` 里有升级步骤；补丁被跳过时，系统体检显示警告。

### T3.5 磁盘与日志占用
- **做什么**：系统体检增加磁盘剩余空间和 OctoBot 日志大小两项；OctoBot 日志超过限制时提示，或配置日志轮转。
- **验收**：有测试；空间不足时显示“异常”，并给出处理办法。

### T3.6 访问安全
- **做什么**：如果负责人想用手机远程查看，设计一个安全方案，例如通过 Tailscale 等 VPN 访问，并给桥接服务加访问令牌。**不要**直接把端口暴露到公网。
- **验收**：方案文档；令牌开启时，未带令牌的请求返回 401，并有测试。

### T3.7 前端端到端测试
- **做什么**：用 Playwright，在演示数据模式下测设置抽屉、方案切换表单校验、体检显示、手机宽度布局。
- **验收**：在 CI 里运行。
