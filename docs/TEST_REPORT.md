## 二、发现的问题与修改

| # | 问题 | 影响 | 修改 |
|---|---|---|---|
| 1 | `drakkarsoftware/octobot:stable` 于 2026-10-08 指向 3.0.0-beta3，3.0 为“节点模式”，5001 端口没有 `/api/*` | 桥接服务完全读不到 OctoBot | `docker-compose.yml` 固定为 `2.1.1` |
| 2 | Docker 会预先创建空的 `octobot/tentacles`，OctoBot 2.1.1 误以为插件已安装，找不到默认 profile，`KeyError: 'default'` 崩溃循环 | 新电脑首次启动必现 | 手动 `tentacles --install --all`；`start.bat` 首次运行自动安装 |
| 3 | `profile.tradingMode` 显示 “AscendEx” | OctoBot 会把 `tentacles_config.json` 扩写成全部插件，取到了交易所 | 只取 `*TradingMode` |
| 4 | 切换 profile 后权益起点仍是旧值（10000），最大回撤显示 99.7% | 曲线和回撤错误 | 历史记录绑定 profile，切换时重置 |
| 5 | 空单 `size` 为负、杠杆恒为 0 | 合约持仓显示错误 | `size` 取绝对值，杠杆 = value / margin |
| 6 | `SoR` 为 `Virtual` / `Inactive`（仅实盘出现）未判为实盘 | 实盘可能被显示成模拟盘 | 一并判为实盘 |
| 7 | **模拟盘权益算错**：桥接服务用“profile 初始资金 + 回放成交”，但 OctoBot 跨重启、跨 profile 保留模拟资金 | 实测显示 999.84，实际 2193.4 | 改为读取 OctoBot 的组合价值（`/api/historical_portfolio_value`） |
| 8 | OctoBot 重启后先返回空列表再返回历史成交，旧成交被当成新成交 | 日志和 3D 成交动画出现假成交 | 只把时间晚于已知最新成交的记录视为新成交 |
| 9 | OctoBot 断开时驾驶舱切回演示数据 | 每次切换策略都会满屏假数据 | 断开 15 分钟内（或切换中）保留最后的真实数据，并提示“重连中” |
| 10 | OctoBot 重启瞬间组合价值报 0（也可能只计入部分资产） | 可能误触发止损 | 价值 ≤ 0 视为未知；重连后 60 秒内不判断止损；需连续 3 次（约 9 秒）低于止损线 |
| 12 | 交易暂停后 OctoBot 不再报告组合价值，备用止损先触发时桥接服务看不到，不会改为观望 | 重启后会恢复交易 | 备用止损加余量；桥接服务识别“OctoBot 自己暂停了” |
| 13 | OctoBot 重启期间驾驶舱权益短暂显示为 1000（用新配置的初始资金推算） | 显示错误 | 保留最后一次真实值；止损只用当次读到的实时值判断 |
| 14 | 桥接服务在 OctoBot 暂停时重启，之后 OctoBot 恢复返回历史成交，又被当成新成交 | 假成交日志 | 早于桥接服务启动时间的成交一律视为历史 |
| 11 | 电脑休眠/重启后 Docker 拉起容器时网络未就绪，OctoBot 创建交易所失败后卡住（进程不退出，`on-failure` 不会重启） | OctoBot 网页打不开，容器 unhealthy | **未修复**，README 常见问题给出 `docker compose restart octobot` |

## 三、OctoBot 真实接口格式（2.1.1）

样本保存在 `data/api-samples/`（git 忽略）。

- `/api/ping` → `"Running since 2026-10-24 15:07:03."`；`/api/version` → `"OctoBot 2.1.1"`
- `/api/orders`：`symbol`、`type`（如 `"SELL LIMIT"`）、`price`/`amount`（**字符串**）、`time`（**秒级浮点**）、`cost`、`market`、`SoR`（`Simulated`/`Real`/`Virtual`/`Inactive`）、`id`
- `/api/trades`：同上，另有 `fee_cost`、`fee_currency`、`ref_market_cost`
- `/api/positions`：`side`（long/short）、`amount`（空单为负）、`value`、`entry_price`、`liquidation_price`、`margin`、`unrealized_pnl`
- `/api/pnl_history`：`ex_t`、`pnl`、`pnl_a`、`q`、`tc`、`d{en_p, ex_p, en_a, ex_a, s, f, ...}`
- `/api/historical_portfolio_value?currency=USDT&time_frame=1m` → `[{"time":..., "value":"2193.66"}]`（参考货币计价，实时更新）
- 切换 profile：`GET /profile?select=<id>` + `GET /commands/restart`；自动化：`POST /automations?action=save|start`

## 四、测试过程

1. **现货网格（34 分钟）**：16 张单（8 买 8 卖，间隔 400）。15:16 买单 79,512.34 成交 → 立即挂卖单 79,912.34（上方一格），挂单 8/8 → 7/9。期间 BTC 在 79,348–79,912 波动（约 0.7%，不足两格），所以只有 1 笔成交。权益核对：(1000 − 124.36 − 0.25) + 0.016564 × 79,578.83 = 2193.54，与驾驶舱一致。
2. **合约分批补仓**：OctoBot 创建交易所时检查类型，Bitget 插件只声明现货，模拟盘同样报 `NotSupported`（只有回测会跳过检查）；3.0 的 Bitget 插件同样不支持。替代：新增 `astra_spot_dca`（参数相同，Bitget 现货）。
3. **现货分批补仓**：首单 BUY LIMIT 79,396.51（现价 −0.2%），补仓 78,203 / 77,010 / 75,817；金额 87.5 USDT = 组合 2193 的 4%，补仓单 ≈ 6%。监控约 25 分钟加后续数小时，首单始终未成交（价格未回落 0.2% 就被下一轮重新定价），**止盈/止损单未实测**。
4. **bridge 自动恢复**：OctoBot 重启约 3 分钟后自动重连；把 bridge 从 Docker 网络断开 40 秒，恢复后 OctoBot 链路约 5 秒、Bitget 约 30 秒（指数退避上限）恢复。
5. **策略切换**：通过驾驶舱接口从“分批补仓”切到“现货网格”，约 15 秒完成，期间驾驶舱保持模拟盘模式并显示“重连中”，随后出现 16 张网格单；切到合约补仓、`../config` 等非法目标均被拒绝。
6. **止损实测（模拟盘）**，两条路径都验证通过：
   - **OctoBot 内置备用止损**：网格运行中把止损设为 0.01%，20:15:06 BTC 回落时 OctoBot 自动化立即触发：撤销 16 张网格单 → 市价卖出全部 0.016564 BTC（80,465.34）→ 停止策略并暂停交易。**这次测试发现了一个缺陷**：交易暂停后 OctoBot 不再报告组合价值，桥接服务看不到亏损，所以既没记录“已止损”，也没把配置改成观望（之后一重启网格就会恢复交易）。修复：① 备用止损留出余量（你的比例 + max(1, 一半)，例如 10% → 15%），正常情况下由桥接服务按你的比例先执行；② 桥接服务发现“止损已开启、OctoBot 在线、没有挂单、连续 5 次读不到组合价值”时，判定为备用止损已触发，记录下来并改为观望。修复后在同一现场复测：70 秒内识别，配置改为 `astra_idle`。
   - **桥接服务止损（主路径）**：把方案起点调高 0.1% 模拟亏损（止损 0.01%），重启桥接服务后 65 秒（60 秒稳定期 + 连续 3 次确认）触发：OctoBot 执行即时自动化（撤单 → 卖出 → `stop_condition_triggered` 暂停交易）→ 删除即时自动化 → 配置改为 `astra_idle`；驾驶舱顶部出现红色“已触发止损”提示。
   - 测试结束后：OctoBot 运行“观望”，手动方案止损恢复为 10%（起点 2205.56，止损线 1985.00）。

自动化测试（在 bridge 镜像内运行，覆盖字段映射、行情识别、方案、AI 答案校验、止损流程）：全部通过。

## 五、未解决 / 待你决定的问题

1. **AI 多智能体仓位策略待实测**：AI 行情雷达、AI 信号和 AI 自动选策略已完成真实 API + 模拟盘验证；`astra_ai_index` 的多智能体、新闻及情绪源链路尚未验证。
2. **补仓止盈止损未实测**：需要行情回落 0.2% 以上让首单成交。可以在模拟盘长时间运行“分批补仓”观察。
3. **休眠后 OctoBot 卡住**（问题 11）：可以加一个定时检查 unhealthy 就重启的小脚本，或者在 Windows 任务计划里开机延迟启动，**需要你决定是否要加**。
4. **止损只在模拟盘生效**：实盘下桥接服务不会执行卖出（按“全程模拟盘”的约定）。如果以后要在实盘使用，需要你明确同意。
5. **OctoBot 内置备用止损**的起点是 OctoBot 本次启动，比例是你的比例加余量，只在桥接服务停止时起作用。
6. **指数持仓策略在测试的 6 分钟内没有调仓**（OctoBot 也没有日志），原因待查，可能和调仓周期（1 天）或自定义权重需要 OctoBot 账号有关。
7. 切换策略时 OctoBot 有时会重新安装插件，重启需要约 100 秒（文档写的是 1–3 分钟）。
8. 网格、指数模式停止时 OctoBot 会报 “Stopping strategy execution is not implemented”，不影响结果（交易者已暂停）。

## 六、参数建议（基于 Bitget BTC/USDT 近期数据，2026-10-25）

| 指标 | 数值 |
|---|---|
| 现价 | 约 79,600 |
| 30 天年化波动率 | 28% |

| 4 小时 K 中位振幅 | 0.81%（90 分位 1.8%） |
| 1 小时 K 中位振幅 | 0.38%；振幅 ≥ 400 USDT 的占 35%，≥ 800 的占 8% |
| 30 天区间 | 79,238 – 87,232（10%）；90 天 62,270 – 87,394 |
| 指标雷达 | 下跌趋势（ADX 37，EMA20 < EMA50） |

**现货网格**（间隔 400 = 0.5%，上下各 8 档，覆盖 ±3.2%）
- 每格净利约 0.5% − 0.2% 手续费 = 0.3%，间隔合理。
- 覆盖 ±3.2% 偏窄：日均振幅 2.4%、30 天区间 10%，一两天的单边行情就会跑出网格（全部买成 BTC 或卖光）。
- 现在处于下跌趋势，普通网格会持续接货。

**分批补仓**（首单 4%，每跌 1.5% 补 6% × 3，止盈 1.2%，止损 6%，每 4 小时一轮）
- 4 小时窗口里跌到 1.5% 的只有 6%，跌到 3% 的为 0，**补仓单很少会成交**。
- 每轮都会以 −0.2% 重新挂首单，且已成交的仓位和止盈单会保留，**下跌时每天可能累计买入约 24% 资金**，`max_asset_holding_percent` 为 100%（可以全仓）。
- 止盈 1.2% 在单个 4 小时窗口内的达成率约 7%，多数需要跨越多个窗口。

## 七、本次新增功能

- **13 个 ASTRA 预设**（Bitget 现货、模拟盘）：现货网格、移动网格、阶梯挂单、分批补仓、智能补仓、趋势指标、抄底分析、反转信号、指数持仓、AI 信号、AI 仓位、观望，以及标记为不可用的合约分批补仓。
- **设置页 → 交易方案**：手动 / AI 交易 / AI 选策略 / 指标选策略，每个方案单独设置最大止损。
- **行情雷达**：指标判断（ADX、ATR、EMA20/50 斜率、布林带宽度，每 10 分钟）和 AI 判断（DeepSeek，每 30 分钟，约 2 千 token/次），都显示理由。
- **自动切换**：仅模拟盘；连续确认（指标 3 次 / AI 2 次）、置信度 ≥ 50%、每个策略至少运行 12 小时。
- **止损**：从方案启动时的资金算起；触发后撤单 → 全卖成 USDT → 暂停交易 → 配置改为观望；OctoBot 内部另设备用自动化。
- **仓位卡片按策略类型显示**：网格显示区间位置，补仓显示距下一档补仓和止盈，其他策略显示最近挂单距离。

## 八、2026-10-25 接手后的 AI 实测

环境和账户范围与前述测试相同：Bitget 公开行情、OctoBot 模拟盘，没有配置交易所交易密钥。

### 发现并修复

1. 官方 DeepSeek 接口返回的可用模型为 `deepseek-flash`、`deepseek-v4-pro`。本机配置和项目默认模型改用 `deepseek-flash`；AI 信号预设继承服务的模型，不再单独固定旧名称。
2. 驾驶舱的行情 JSON 请求只允许 400 个输出 token。DeepSeek 默认的思考过程也消耗输出预算，现场出现过正文为空、报“没有返回 JSON”。这条短分类请求关闭思考模式，并明确拒绝被截断的答案；其他兼容接口不附加 DeepSeek 专用参数。
3. AI 信号预设使用了旧字段 `max_confidence_threshold`，当前插件实际读取 `min_confidence_threshold`。改用有效字段，保留原预设意图的 60% 门槛。
4. AI 自动切换的连续确认现在同时核对行情状态和推荐策略，避免“同样震荡、但两次推荐不同策略”也被算作确认。指标方案继续只核对行情状态，确认次数显示为真正连续的次数。
5. 非有限、越界或布尔置信度，以及格式不合法的理由，均被拒绝。服务端错误信息先脱敏再截短，避免泄露完整或半截 API Key；`.dockerignore` 排除本机凭据、运行数据和 Git 目录。

### 结果与证据

| 验证项 | 观察结果 |
|---|---|
| DeepSeek 认证与模型发现 | 官方 `/models` 请求成功，只解析本机配置，不打印 Key |
| 驾驶舱真实 AI 行情请求 | 返回结构化 `down` / `astra_idle`，约 1,600 token/次，无解析错误 |
| OctoBot AI 信号 | 服务成功加载 DeepSeek Flash；`GPTEvaluator` 收到 `down 62%`，模拟盘没有新增买单 |
| AI 自动选策略 | 连续两次返回 `down` / `astra_idle`、置信度 0.72，触发真实的 OctoBot 模拟盘策略切换 |
| 切换完成 | `AI 信号 → 观望`，约 20 秒后重新连接；0 挂单，模拟权益 2205.56 USDT |
| 自动化回归 | `python -m unittest discover -s tests -v`，13 个测试通过，覆盖请求兼容、答案校验、连续推荐、低置信度/实盘拦截和密钥脱敏 |
| 构建 | `docker compose build bridge` 通过，已加载修复后的镜像 |

为在一次测试中验证真实切换，测试期间临时清除了模拟盘的历史冷却时间戳；12 小时参数没有改变，测试结束后已还原原始方案状态。

最终运行状态恢复为：`astra_idle`、手动方案、止损 10%、方案起点 2205.56 USDT。DeepSeek 配置保留在被 Git 忽略的本机 `.env`。

原始接口观察记录在本机 `data/handoff-20261025-134033/`，不提交仓库。以上结果仅验证功能执行，不证明 AI 判断准确率或策略盈利能力。剩余事项见 `docs/HANDOFF.md`。
