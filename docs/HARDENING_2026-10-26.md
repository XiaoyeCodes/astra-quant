## 二、本轮修改与验证

1. **跨站与 DNS 重绑定防护**（`bridge/app/security.py`）：所有请求校验 Host；写操作和 WebSocket 校验 Origin，写操作必须是 `application/json`。
   - 实测：跨站 `text/plain` POST、跨站 JSON POST、`Host: evil.example` 读取 `/api/state`、跨站 WebSocket 全部 403；同源 POST 200、WebSocket 101、Docker 健康检查正常、驾驶舱页面无 JS 报错。
2. **OctoBot 看门狗**（`tools/octobot_supervisor.py`）：OctoBot 作为子进程组运行；首次启动宽限 15 分钟，之后连续 10 分钟无响应就结束并以状态 1 退出，由 `restart: on-failure` 重启容器。`docker stop` 先调用 OctoBot 自己的 `/commands/stop`（OctoBot 不响应 SIGTERM），再兜底 SIGTERM/SIGKILL。
   - 实测：`docker stop` 3.8 秒正常退出、退出码 0（原来要被强杀）；用 SIGSTOP 冻结 OctoBot（缩短时限的测试配置），45 秒后看门狗重启容器，16 秒后 OctoBot 恢复响应。
3. **止损核实**：先每秒执行“撤单 + 全部卖出”，从 OctoBot 持仓表核实“没有挂单、只剩 USDT（低于 1 USDT 的零头忽略）”连续两次，再单独暂停交易、删除自动化、改为观望。60 秒内核实不了也会暂停，但记录为“止损未完全执行：…”并醒目提示，不再报假完成。
   - 实测（指数持仓 BTC/ETH/SOL 三币）：SOL 1.9532、ETH 0.1287、BTC 0.006222 全部市价卖出，核实“只剩 USDT 997.15”，`verified: true`，交易暂停，配置改为 `astra_idle`。
4. **模拟资金重置识别**：本轮重建 OctoBot 容器时，OctoBot 把模拟资金从 2200.10 重置为配置初始资金 1000，桥接服务把它当作 −54.55% 亏损执行了止损（核实环节正确报告了只剩 USDT 1000）。修复：OctoBot 离线期间不会交易，所以重连后稳定的权益与离线前相差超过 5% 时，判定为模拟资金重置，把止损起点改为新值并记录、通知，而不是清仓。离线前的权益会持久化，桥接服务重启也能识别。**残余风险**：若真实行情在 OctoBot 离线期间波动超过 5%，这部分不会触发止损。
5. **通知**（`bridge/app/notify.py`）：风险级事件（止损触发/核实/失败、方案启动、策略切换）全部推送；OctoBot 计划外离线超过 2 分钟推送一次，恢复时再推送；AI 失败每小时最多一次。后台发送、失败重试 3 次、相同消息去重，不影响交易逻辑；Telegram 出错时不会把 token 写进日志。设置页有“发送测试通知”。
6. **审计日志**（`bridge/app/audit.py`）：`data/logs/astra-YYYY-MM-DD.jsonl`，保留 30 天；实测重启后控制台恢复 32 条历史。
7. **OctoBot 密码登录**：OctoBot 开启网页密码后，在 `.env` 填 `OCTOBOT_PASSWORD`，桥接服务自动登录（读取 CSRF 令牌、保持会话），失败时每分钟最多重试一次，避免被 OctoBot 封禁。
8. **固定依赖版本**、**GitHub Actions CI**（Python 测试、前端测试与语法检查、构建桥接镜像）。

测试：Python 66 项（原 30 项 + 新增 36 项）、前端 4 项全部通过。

## 三、仍未解决 / 需要你决定

1. **是否给 OctoBot 网页设置密码**：可以堵住其他网页通过 OctoBot 的 GET 接口停机或切换策略的风险。代价是打开 OctoBot 页面时需要输入密码。设置方法：OctoBot → Accounts → Interfaces → Web interface 设置密码并勾选需要密码，然后在 `.env` 填同一个 `OCTOBOT_PASSWORD`，重启。
2. **配置通知渠道**并点击“发送测试通知”确认能送达（Telegram 在国内需要设置 `NOTIFY_PROXY`）。
3. **实盘风控**：止损和自动切换目前只在模拟盘工作。
4. **平台天花板**：OctoBot 2.1.1 切换策略必须重启；Bitget 合约不可用；升级 OctoBot 需要重新验证启动补丁。要从根本上解决，需要评估换执行引擎（例如直接基于 ccxt 自研执行层），工作量大。
5. **策略可信度**：需要回测和更长时间的单策略模拟；模拟手续费 0.2% 的来源仍待查。
6. **你的模拟账户余额**：因为 OctoBot 重置，模拟资金从约 2200 USDT 变成约 1000 USDT。这是模拟数据，不影响真实资金，但之前的模拟收益曲线已经不连续。
7. **Docker Desktop 自身故障**：今天电脑重启后 Docker Desktop 启动即崩溃（残留的 `docker-secrets-engine\engine.sock`），已通过 WSL 删除该文件恢复。README 常见问题已写明处理方法。
